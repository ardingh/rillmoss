# 日常启用与自动发布决定

用户于 2026-09-12 明确要求：“先正式启用吧，以后有问题再改。并且把本地在用的 conf 更新”。本版本据此采用显式用户授权作为发布依据，不把尚未完成的设备验收改写为通过。

## 本次范围

- 补回 `DOMAIN,api64.ipify.org,V3 Static Residential` 精确前置规则，个人输入和生成器同步保留；其他分流、分组、节点连接设置不变。
- 每日及手动来源任务全部成功时，自动采用并写回完整配置、快照和版本；来源下载失败、条数异常、出口约束失败、完整校验失败及远端提交变化仍会阻止不安全写回。
- `policy/release.json` 设为发布开启，`acceptance` 保持 null；`user_authorization` 仅覆盖当前个人策略及每日来源数据更新，不授权自动改变分组、来源范围或新增功能。
- 用户手动完成客户端配置导入、切换和 VPN 重连。仓库配置文件更新不等于客户端已经加载。

## 保留的限制

- 住宅节点名称缺失时，原单成员 AI 分组已观察到回退普通 V3；不能把该结果说成住宅配置正确时的所有线路故障均会回退。
- iPhone、IPv6、UDP、部分真实应用功能与设备更新验收尚未全部完成。本次检测规则修复已经过本地测试和完整配置校验，尚无设备复测证据。
- Claude Check 仍读取旧规则文件作静态检查；本次仅修复检测域名的实际出口，不改检查器。
- 已终止的保护节点试验不再自动执行。后续出现问题时按实际场景处理，历史记录保留。

## 停止和恢复

将 `publish_enabled` 改回 false 并普通提交到 main，可暂停后续自动采用，既有每日任务继续检查和保存候选。用户可手动恢复此前备份配置。公开提交可以由后续普通提交纠正，但已经被他人取得的内容无法收回。

此决定不改变自动 rollback 对“已完成设备验收且版本一致”的要求；仅有用户先行启用授权的版本，不会被工具冒充已验证的回退目标。
