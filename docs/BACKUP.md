# 完整备份与离线恢复

备份保存一个完整发布版本：`rillmoss.conf`、全部 `snapshot/` 原文和输入、`policy/`、生成代码、测试、文档、版本信息及校验报告。不依赖上游仍能访问。它不包含节点连接参数、设备配置数据库、私有日志或主工作树尚未公开的修改；恢复规则项目不能替代恢复 Shadowrocket 节点。

## 每月 15 日归档

`Monthly complete rule backup` 的 `backup.yml` 发布到 main 后才生效：

- 台北时间每月 15 日 09:18 计划触发，通常在每日 08:08 来源检查之后。
- 每日来源检查结束时也触发，不要求来源检查成功。15 日之前不归档；15 日起若当月缺档则补做，重复执行直接结束。
- 每次读取当时可信的 main，确认工作树干净、提交仍为远端 main，并离线校验完整快照；不再次下载来源，不写回 main，不改变规则或自动发布开关。
- 创建附有说明的日期标签，例如 `backup-2026-09-15`，固定整个已发布提交。标签不随 main 更新，不自动过期或清理；不覆盖同名标签、不强推、不创建 Release。
- 标签说明记录提交、计划日期、实际归档时间、规则原始生成时间、快照标识、条数、最近来源检查时间及结果。若来源失败，保存最后完整版本；不把归档日期冒充规则更新日期。
- GitHub 调度可能延迟或漏跑。只补当前月份，不伪造往月或漏跑当天的历史快照。若整月平台都未运行，恢复后需人工选择历史提交处理缺档。

可在 Actions 手动运行 `backup.yml`；仍遵守每月 15 日起、每月一次的条件，不提供强制覆盖或伪造日期入口。检查未通过或 Git 操作失败时任务标红，沿用 GitHub 原生失败通知。月度流程只串行自身，不挤占每日发布的排队位置；遇到 main 更新竞态时停止，由下一次运行从最新 main 重试。

从仓库的 **Tags** 页面下载指定日期的 ZIP / tar.gz，可取得完整文件树。Git 标签和提交说明只有在 Git 仓库或 bundle 中才完整保留，普通源码压缩包不含 Git 历史。查看标签说明：

```sh
git show --no-patch backup-2026-09-15
```

月度标签属于同一 GitHub 仓库，不能防仓库被删除或平台不可访问。完整离线副本需要在仓库之外保存。

## 完整离线副本

离线交付包包含以下内容，具体日期、提交与文件校验值以包内记录为准：

| 文件 | 内容 |
|---|---|
| `published-project.tar.gz` | 当前已发布提交的完整文件树，可直接解压使用 |
| `published-history.bundle` | 从初始提交到该发布提交的完整可达 Git 历史 |
| `BACKUP.json` | 备份时间、真实规则时间、来源提交与校验值 |
| `SHA256SUMS` | 交付包文件的 SHA-256 校验值 |
| `RESTORE.md` | 不依赖原项目目录或网络的恢复步骤 |
| `verification.json` | 本次从压缩包和 Git bundle 实际恢复、比对的结果 |

这是用户明确要求的一次离线导出，不安装本机定时服务。离线包应长期保留；同一台 Mac 上的副本可以防项目目录丢失，无法防整块磁盘损坏。

恢复时在新目录解压或从 bundle 获取历史，不覆盖现有项目。运行环境需要 Python 3.11+ 与 Git；生成器使用 Python 标准库，离线校验和重建不需要 curl、上游网站或 GitHub。先在解压后的项目目录执行：

```sh
python3 -B -m rillmoss verify --bundle .
python3 -B -m rillmoss rebuild --bundle . --output rebuilt.conf
```

重建结果与包内 `rillmoss.conf` 应逐字节一致，输出文件必须尚不存在。验证完整性不等于设备验收通过。回退到线上仍按维护与发布边界审阅确认；设备导入、配置切换及 VPN 操作由用户手动完成。
