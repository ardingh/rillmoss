## A. 操作前

1. 两端记录 Shadowrocket 版本、系统版本、配置模式、精确节点名称、当前配置和更高优先级模块。记录仅放 `private/acceptance/`，不要附私密原始日志到仓库。
2. 将当前设备配置导出备份到本地 `private/`，确认可重新选择；不删除或改名原始节点。住宅节点应“代理通过”精确的普通 V3。
3. 确认当前软件能解析三个单成员 select 分组和全部配置设置。按名称绑定，不能用包含字符串的模糊筛选。
4. 用户明确要求：断开 VPN、导入和切换配置、修改节点、重连 VPN 均由用户手动操作。助手先给出步骤，等用户确认完成后再继续读取状态和检查，不代替用户操作。关闭旧 AI 会话与旧连接后再测试，温和策略可能保留既有 TCP 连接。

## B. 先用无账号探测检查出口与失败行为

正常连接可直接使用 AI 主域名的公开 `/cdn-cgi/trace` 端点，以不携带账号、cookie 或 token 的 HTTPS 请求检查实际出口。故障测试使用独立副本，复用同样的策略结构，把无账号的公开 IP 回显目标分别加入 OpenAI / Claude 组；副本中现有 AI 规则暂时 REJECT，且手动退出 AI 应用及相关浏览器，减少后台账号请求风险。记录成功请求实际出口；仅看策略名称或延迟值不算通过。测试副本不含更新地址，不作为可发布成品。

| 场景 | 预期与记录要求 |
|---|---|
| 正常节点链 | 2026-09-10 Mac IPv4 初测通过：ChatGPT / Claude 回显出口均与住宅节点地址一致，普通境外对照与普通 V3 一致；见下方记录 |
| 更换首页默认节点 | 两组继续走住宅；新连接结果不随首页改变 |
| 住宅节点不存在 | 2026-09-10 Mac 测试失败：两个组都回退到普通 V3；必须修复并复测 |
| 住宅节点不可达 | 仅对测试副本设置不可用的本地测试端口；请求失败，不出现普通 V3 / DIRECT 出口 |
| 中转节点不存在 | 在隔离的测试住宅副本中设置不存在的中转别名；请求失败 |
| 中转不可达 | 只改隔离测试副本，中转不可连接；请求失败 |
| IPv4 | 明确使用 IPv4 目标，正常与上述故障均得到预期 |
| IPv6 | 在实际可用的 IPv6 环境中测试正常和故障；环境不可用须标“未测”，不能填通过 |
| UDP / QUIC | 使用可观察的测试接收端，验证代理侧 QUIC 被阻断、不支持 UDP 时 REJECT，故障不直连。curl 的 TCP 成功不能代替 UDP 验收 |

如果缺失住宅节点导致软件自动选首页节点或 DIRECT，单成员 select 的方案就没有满足要求：立即停止候选启用，记录实际行为，返回实现阶段解决。`close-if-proxy-chain-missing` 只保护中转缺失，不能作为住宅异常通过的证据。

无账号故障探测通过后，先在住宅出口保护下收集真实 AI 服务请求，检查新域名是否落在住宅规则内。不要先让未知端点用登录态访问后再检查出口。独立的 GitHub、包仓库或用户指定外部站点按目标地址正常分流。

## D. iPhone 与配置更新

公开仓库的稳定地址已通过 HTTPS 下载及文件校验；这不等于设备更新验收。恢复设备验收后，分别记录“候选文件的加载与错误恢复”和“设备从本人地址更新”。Mac / iPhone 的设备加载、故障保护与恢复结果仍需真实通过，才能启用成品自动发布。

需要修改的是两个 AI 策略组的节点缺失处理；域名列表和打底来源不因这次结果调整。已准备仅本机使用的 REJECT 保护写法试验，不改当前成品：使用精确完整名称筛选，将 REJECT 保留为固定项；必须先证明缺失时拒绝，再验证住宅正常时能连通、且实际出口正确。不能把“始终拒绝”当作完整修复。
